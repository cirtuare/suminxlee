식샤 : 서울대학교 식단 앱

프로젝트 내용
* MAU 10,000의 서울대학교 학식당 서비스
* 팀 구성
    * PO 1 / 프로덕트 디자인 2 / 서버 4 / 데이터 2 / 웹 4 / 안드로이드 3 / iOS 4
* 주요 기여 내역
    * 식단 카카오톡 공유하기 기능 제안 및 개발
    * Fastlane 애플 개발/배포 인증서 관리 도입
    * 2년간 여러 신규 기능 개발 (프로필 수정, 나의 평가 관리 등) 및 디자인 리뉴얼, 리팩토링 진행

발생문제 및 해결방법
1. 네이버 지도 SDK 인증 방식 변경 대응
* 문제 : 네이버 지도 SDK 업데이트로 기존 clientId 기반 인증이 동작하지 않아 지도가 표시되지 않는 버그 발생
* 해결 : NMFAuthManager의 인증 프로퍼티를 신규 방식인 ncpKeyId로 변경하고, Config.swift / Info.plist / AppDelegate의 키 이름을 일괄 수정. 아울러 NMFMapView → NMFNaverMapView로 뷰 타입을 교체하고, 기존에 임시로 하드코딩되어 있던 위경도 오차 보정값도 함께 제거하여 정리했습니다.
2. 나의 평가 관리 화면 구현 시 리팩토링
2.1 MealID만으로 Meal 정보를 조회할 수 없는 문제
* 문제 : 내 리뷰 목록 API 응답에는 mealId만 포함되어 있었으나, 기존 코드는 Meal 객체 전체를 전달받는 구조여서 나의 평가 관리에서 리뷰를 탭했을 때 상세 화면으로 진입이 불가능했습니다.
* 해결 : MealInfoViewModel에 mealId 하나만으로 API를 호출해 Meal 정보를 가져오는 getMenuFromId(id:) 메서드를 추가했습니다.
2.2 MealReviewView가 새 리뷰 작성 전용으로 설계되어 수정으로는 진입 불가한 문제
* 문제 : MealReviewView,MealReviewViewModel이 항상 빈 상태로 시작하는 구조여서, 기존 리뷰 데이터를 채운 상태로 열거나 수정 API를 호출할 수 없었습니다.
* 해결 : 뷰 진입 경로를 새 리뷰 등록 / 기존 리뷰 수정 두 가지로 이분화했습니다. 수정 모드에서는 기존 리뷰의 별점·텍스트·이미지를 초기값으로 주입받아 표시하고, 제출 시 수정 API를 호출하도록 처리했습니다.
3. 리뷰 수정 API의 이미지 재전송 구조적 한계 파악 및 대응
* 문제 : 서버의 리뷰 수정 API가 이미지를 multipart 바이너리로만 받는 구조로, 이미지를 변경하지 않는 경우에도 기존 이미지를 서버에서 재다운로드한 뒤 다시 업로드해야 하는 문제가 발생했습니다. 방치 시 1) 동일한 이미지가 수정마다 새 URL로 중복 적재되어 스토리지가 낭비되며, 2) 다운로드 후 재압축을 반복하므로 이미지 화질이 점진적으로 저하되는 문제를 어렵지 않게 연상할 수 있었습니다.
* 대응 : 근본적으로는 기존 이미지는 서버 URL 문자열만 전달하고, 새 이미지만 바이너리로 업로드하는 API 설계 변경이 필요한 문제임을 파악하여 이를 서버 팀 및 다른 클라 팀들에게 전달했습니다. 다만 배포 일정을 고려해 서버 팀과 논의 후, 서버 팀의 어렵다는 답변을 받아들여 현행 방식을 우선 유지하기로 결정하고, 이를 백로그로 정리해 두었습니다.

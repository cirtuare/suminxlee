프로젝트 내용

* 위치 기반 로컬 맛집 추천 서비스
* 팀 구성
    * (~2025.2.) PM 2, 디자인 3, 서버 2, 안드로이드 4, iOS 3
    * (2025.3. ~ 2025.11.) PM 1, 디자인 1, 서버 1, 안드로이드 2, iOS 2
* 주요 기여 내역
    * 앱 구조(아키텍처)를 직접 제안 및 설계하여 iOS 개발을 주도했으며, PM/디자인/안드로이드/서버 팀 간의 소통을 리드해 개발 우선순위를 조율, 앱스토어 출시 전 과정을 총괄함
    * Apple의 Photos 프레임워크를 활용하여 메모리 사용을 최적화한 커스텀 사진 앨범 선택 기능 구현
        * https://github.com/AconInc/ACON-iOS/pull/13
    * CoreLocation 프레임워크와 Multicast Delegate 패턴을 적용해 확장성 높은 LocationManager를 설계하고, 이를 네이버 지도 API와 연동하여 위치 인증 시스템 구축
        * https://github.com/SOPT-all/35-APPJAM-iOS-ACON/pull/10
        * https://github.com/AconInc/ACON-iOS/pull/189
    * 사용자 행동 패턴 트래킹을 위해 PM 측에 Amplitude 도입을 제안하고, 커스텀 AmplitudeManager 클래스를 구현해 데이터 분석 환경 세팅
        * https://github.com/AconInc/ACON-iOS/pull/80

발생문제 및 해결방법

1. 커스텀 앨범 구현 — 메모리 최적화
* 배경 : 디자인 스펙에 맞는 커스텀 앨범이 필요해 Photos 프레임워크로 직접 구현했으나, 수천 장의 사진을 빠르게 스크롤하면 메모리가 급증해 앱이 종료되는 문제가 발생했습니다.
* 고민 : 출시 2주 전이라 iOS의 기본 사진첩 라이브러리로 교체하자는 의견도 있었으나, 디자인 요구사항을 포기하고 싶지 않아 직접 해결하기로 결정했습니다.
* 해결 : Xcode Instruments로 메모리 누수 지점을 먼저 파악한 뒤 아래 전략을 적용했습니다.
    * NSCache 기반 이미지 캐싱 도입 → 이미 로드한 이미지를 재할당 없이 재사용
    * 스크롤 감지 시 50개씩 불러오는 페이지네이션 적용 → 전체 일괄 로드 제거
    * 썸네일은 저해상도로 요청, 사용자가 선택한 경우에만 원본 고해상도 호출
    * 화면에서 벗어난 셀의 이미지 로드 요청 즉시 취소 (cancelImageLoad)
    * 모든 이미지 로딩을 비동기 백그라운드 스레드에서 처리
    * 앱 사용 중 사진 접근 권한이 변경될 경우를 대비해 권한 변화 실시간 감지 처리 추가
* 결과 : 약 일주일간의 디버깅 끝에 메모리 사용량을 90% 이상 줄였으며, 디자인 요구사항을 반영한 커스텀 앨범을 예정대로 출시했습니다.
* Reference
    * https://github.com/AconInc/ACON-iOS/pull/13
2. 버튼 컴포넌트화 및 글라스모피즘 시스템 재정립
* 배경 : 앱 전반의 버튼들이 글라스모피즘 스타일로 통일되어 있었으나, 각 화면마다 동일한 스타일 코드가 중복 작성되어 있었습니다. 디자인 시스템이 변경되거나 버튼 상태(활성/비활성 등)를 일관되게 처리하기 어렵다는 문제를 느끼고, 팀 전체의 생산성을 위해 리팩토링을 제안하고 직접 진행했습니다.
* 해결 : 두 축으로 나눠 재정립했습니다.
    1. 글라스모피즘 시스템 재정립
    * 기존에 메서드 단위로 흩어져 있던 블러·보더·배경 처리를 GlassmorphismType으로 타입화하고, GlassmorphismView으로 일원화했습니다. 배경 글라스모피즘과 테두리 글라스모피즘을 분리하여 조합이 자유롭도록 설계했습니다.
    1. 버튼 컴포넌트화
    * ACButtonType 프로토콜을 정의해 버튼 외형(타입) 스펙을 선언적으로 표현하고, 이를 채택한 ACButton 공통 컴포넌트를 구현했습니다. GlassButtonState를 별도로 두어 버튼 상태 변화에 따른 UI 업데이트를 컴포넌트 내부에서 자동으로 처리하도록 했습니다.
* 결과 : 새로운 버튼이 필요할 때 타입만 추가하면 되는 구조가 갖춰졌고, 팀원들이 이후 작업에서 버튼 구현 공수를 크게 줄일 수 있었습니다.
* Reference
    * https://github.com/AconInc/ACON-iOS/pull/130
    * 팀원을 위한 사용법 정리 문서
